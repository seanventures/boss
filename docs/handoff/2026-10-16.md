## How to work (operator's rules)

- **Tests:** run only the tests for the code you change while working. Run the full engine + API
  suites **once, right before merging to main**, then re-run only the failures against
  `origin/main` to separate new failures from pre-existing ones. No CI on PRs (private repo).
  Tiers and commands: `docs/operations/TEST_TIERS.md`.
- **Test databases:** API tests need a database name containing `test`. Some engine tests need a
  database seeded like a real install (`python -c "from boss_engine import bootstrap;
  bootstrap.seed()"`); the identity audit tests need an unseeded one. `tests/known-failures.txt`
  lists the 10 failures that are expected (each with a reason).
- **Merging and releases:** nothing goes to main without the operator's go. A release is a tag plus a
  GitHub pre-release (`BOSS v1.0-rcX`), only when the operator asks. Small improvements merge
  without a tag.
- **Plane** is the source of truth for what is open. Keep it accurate: mark Done only what is
  merged; split leftovers into new tickets. Scripts used: `plane-update.sh`, `plane-done.sh`,
  `plane-export.sh` (export includes descriptions and comments).
- **Cost:** avoid parallel sub-agents unless the operator approves; long sessions get expensive.
