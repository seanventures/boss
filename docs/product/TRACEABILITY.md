## Current Highest-Risk Gaps

1. Live external IdP rollout requires provider configuration, secrets, and production identity-provider rollout policy.
2. Real Slack/email sends remain disabled by default until explicit policy, provider credentials, and rollout choices are configured.
3. Broader production promotion and non-sandbox infrastructure targets remain intentionally disabled until explicit policy, credentials, and deployment targets are configured.

## Assumptions and Decisions

- API key and OIDC auth protect `/v1/*` routes when enabled, while keeping `/health` public for liveness probes.
- Project/org member authorization remains separate from transport authentication: API keys and OIDC JWTs identify clients, while project and org members authorize the actor represented in mutation payloads. When `BOSS_API_KEY_PRINCIPALS`, `BOSS_OIDC_PRINCIPAL_CLAIM`, or `BOSS_OIDC_SUBJECT_PRINCIPALS` are configured, the authenticated principal must match the claimed actor.
- Slack/email real delivery and real infrastructure provisioning fail closed unless policy and provider credentials explicitly permit them.
