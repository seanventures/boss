Design notes
  1. 1 Full width: the page drops the console's max-width and side padding. Three panes: changed-file tree (filter, Changed/All files, comment dots, +/−), the diff in the middle (Shiki, split or unified), and the PR agent on the right. Under 1100px the agent pane folds into a button; on a phone it's just the diff.
  2. 2 The header is two lines with no prose. "Where it lives" (clone URL, branch, bare repo path, boss clone) moves into the Clone popover, like GitHub's Code button.
  3. 3 Compare any base…head: main, any commit, or "Since my review". "Viewed" ticks are kept per person.
  4. 4 The PR agent is the agent that built the change. The chat goes to that change's task (steer). "Fix 2 open comments" sends every open human comment and starts a fix run on the same branch. Each comment shows "fixed in <sha>" when the agent closes it. Comments made with git (boss review) show up here too.
  5. 5 Commits: one click shows that commit's diff; ticking two compares them. Each commit says which comments it fixed.
  6. 6 Conversation: the summary is cut to 3 lines, then a timeline of short events. The long checklist the page shows today becomes the Checks tab.
  7. Code tab: the same tree on the left with all files, a file view on the right, at this change or any commit.
  8. New API: /local-changes/{n}/compare?base=&head=, /commits/{sha}, and the change's agent thread (reusing the task steer endpoint). Comments already exist.
  9. 7 One page, two sources. The same tabs, tree, compare, comments and agent work for a GitHub PR. BOSS reads the files, commits, compares, checks and review comments from GitHub, and writes comments, resolves and merges back to it. A comment added in BOSS is posted on GitHub as you when your GitHub account is linked, otherwise by the BOSS app "for Param". Comments made on GitHub appear here within seconds (webhook, with polling as a backup). Open on GitHub stays one click away. If GitHub is down, the page shows the last copy and queues new comments.
