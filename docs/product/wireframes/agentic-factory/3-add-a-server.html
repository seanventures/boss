Design notes: a server onboards itself, like a repo does
  1. 1 One input. An address, user@host, an ssh line or a sentence. The probe shows what it can already see (port, host key) before any credential.
  2. 2 The single human step is handing over access. It is on the list in Where people decide (Secrets and credentials), so it is drawn amber and set apart. The agent detects that the key landed, so there is no “I ran it” button.
  3. 3 Agent actions says what the machine is for (a role: staging, prod or builds, never an app) and lists what the agent will do.
  4. 4 Six boxes, each with a popover. Every old field is still reachable, prefilled.
  5. 5 One primary, Add and set up.
  6. 6 Lands on the server page with the setup as a diagram and a live log. No app moves: each app picks servers on its own Deployments tab, where this one now appears as ready. Prod is never picked for you.
  7. 7 After setup the Infra agent owns the host: it prunes cache alone, and asks only when the fix is outside (DNS) or on the list.
