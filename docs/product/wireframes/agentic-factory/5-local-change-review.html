Design notes: review locally, like git, and take it to GitHub later
  1. 1 Where it lives answers “which folder”. The code lives in BOSS’s Docker volume, not a folder on the Mac, and the strip says so. The clone URL is the way in. Each value has a copy button.
  2. 2 Get a working copy: pick a folder, clone, open. It runs the same boss clone line it shows. The token goes to the keychain, never into the URL.
  3. 3 Code tab: a tree with changed files (M/A) and comment counts, and the whole file with syntax colour at this change or at main. A file name in the diff opens it here.
  4. 4 One comment store. A comment is anchored to file, line, side and commit. The diff, the Code tab and boss review all write to it. A resolved thread keeps the agent’s “Changed in commit …” reply.
  5. 5 Request changes answers the review decision. It starts a fix round on the same branch. Merge waits while human comments are open.
  6. 6 In the fix round, human comments are required inputs, people’s first. Each one is ticked when the agent replies Fixed (with a commit) or Disputed (with a reason). The person resolves.
  7. 7 Plain git works: clone, pull, push a branch, and the branch becomes a change. A push to main is refused: main moves only through the governed merge. boss review writes to the same store. Git notes are an optional offline transport.
  8. 8 Publish carries comments as PR review comments: inline when the line is in the PR diff, else in the review body. Each one is signed with the person and the date. Resolved threads are resolved on GitHub too.
