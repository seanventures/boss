Design notes: monitoring sets itself up the way onboarding does
  1. 1 One input: a project app, a URL, or a few words about what matters. Detection picks the path. Nobody has to know how their app emits telemetry.
  2. 2 The SRE agent reads the running app (/metrics, logs) and the code graph. It turns “replies stop sending” into concrete watches with a 7-day baseline and backtest. Additions from the code (SLA job, sign-in) are dotted-underlined.
  3. 3 Six boxes, each changed through a popover. The strip shows what the agent may do alone vs. what waits. That split comes from Where people decide, not from per-rule checkboxes.
  4. 4 One primary, Start watching. Nothing is pasted into the app, and nothing is redeployed when /metrics already exists.
  5. 5 The rule builder lives on as chips in the popover, and the PromQL stays visible.
  6. 6 Lands on the app’s health page with the agent already on call. It asks only one thing: verify the outside channel (Talking to the outside).
  7. 7 The first incident shows what changes: on staging the agent fixes it alone. On prod the same fix waits for one click.
