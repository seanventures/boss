Design notes
  1. 1 One input. BOSS looks the name up on GitHub (public API) and says whether it is a user or an organisation, and whether you are already connected.
  2. 2 Agent actions: the path BOSS chose, as steps. The default is always the app you already own; a token is never the first suggestion.
  3. 3 Shown only when the app is private and the account is not its owner (the case today). BOSS detects the change by reading the app's public page; no confirm button.
  4. 4 The install link is aimed at the account (install_app_on with its id). The words cover the one thing GitHub may need: switching accounts. BOSS polls the app's installations and moves on when the new one appears.
  5. 5 The token path stays for locked-down orgs, with GitHub's page prefilled; the custom-app path stays too (parity).
  6. 6 The new installation's repositories, with "used by" tags; allowing them runs the existing access check.
  7. Later, a separate change: "Sign in with GitHub" for a person's own account can use the same app's sign-in instead of a second OAuth app.
