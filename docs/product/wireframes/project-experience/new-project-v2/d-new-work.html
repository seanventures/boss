Design notes — New work as a small modal (replaces the one-line composer)
  1. 1 Opens from the header’s New work, from the bar that replaces the composer on Project › Work (typing there opens it with your words), from N, and from an Ask-Helm answer’s “New work” card (prefilled, never sent). Kind tabs: Feature · Bug · Ticket or link. A pasted GitHub/Plane link is read on any tab.
  2. 2 The words are a multi-line box. Helm rewrites them into Here’s what I understood: title · what changes · done when (acceptance) · area from the code graph · risk. Same pattern as Add a project: Looks right / Fix it / Rewrite with a hint; Helm’s additions are dotted-underlined.
  3. 3 Talk it through: at most 4 turns. Helm asks one clarifying question with quick replies; answers update the brief (marked “+ from chat”) and the defaults. Optional: you can start without answering. Longer talks move to Ask Helm with this draft attached.
  4. 4 Picked for you: workflow (default per kind, with its steps and the approval points in amber), priority, estimate (time and cost from this project’s runs), issue (link or create), who to tell, target (staging). Each chip opens a popover; More holds crew, connector, branch.
  5. 5 The plan preview shows who does each step and where you step in.
  6. 6 A refusal for something the project lacks shows the same readiness panel as today, inside the modal; the primary becomes Start anyway and unlocks only when every missing item is ticked.
  7. 7 One primary: Start (⌘↵), which confirms the brief as shown. Add to Next plans it for later in Planned, at Marshal’s rank. Esc keeps the words as a draft.
