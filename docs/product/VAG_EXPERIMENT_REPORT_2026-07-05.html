The single causal finding: holding the cheap generator constant and changing only who verifies moves the pass rate from 0–20% to 60%. Verification quality — not generation quality, not model diversity — is the binding constraint. Across all 46 runs: zero false passes — every gate verdict is binary and fail-closed; nothing substandard shipped.

Note: experiments 2 and 3 executed inside one operational batch (bake_6620989d17) but are separate experiments — different strategy, analyzed separately below.

Method (unchanged from v1, abridged)

Sample project paramg/boss-sandbox; five deterministic stdlib-Python tasks with explicit acceptance criteria; strict profile, risk tier 2–3; PRs suppressed. Per task: design → QA agent authors tests before any implementation → separate implementer agent (forbidden to touch tests, hash/diff-enforced) → BOSS executes the tests itself → fresh-context adversarial review → security review → consistency check → full-suite regression → mutation probe → fail-closed binary gate (every check must be green; no partial credit). "Gate pass %" = passing runs ÷ 5 tasks. Costs from per-call telemetry (llm_calls); experiment 4's from OpenRouter billing deltas. Experiments 1–3 ran working stages as host subprocesses; experiment 4 in per-stage Firecracker micro-VMs.

The ×5 pattern: most of Qwen's security reds are NO VERDICT (prose without the required CLEAN/ISSUES line) — fail-closed protocol failures rather than findings. Its generator seats also produced 2 failing suites and 3 mutation-escaped test sets.

Analysis. The confound that became the finding: these configs put the cheap model in the reviewer seats too. Holding the generator constant across experiments 2–4: DeepSeek code judged by Claude passes 60%; judged by itself, 0–20%. Cheap verification fails in three distinct, now-documented ways — miscalibration (hallucinated PRD clauses), protocol non-compliance (no parseable verdict → fail-closed), and context drift (reviewing the wrong task) — on top of cheap generation's real defects. "Cheap everything" fails twice.

Cross-cutting analysis

  • The amplifier is trustworthy: 46 runs, 24 fail-closed refusals, zero false passes — including mechanical catches no model voted on (GLM's test-tampering; DeepSeek's empty diffs). Formal false-pass instrumentation (known-bad probes) ships with Phase 1.
  • Where quality comes from, ranked: (a) who authors/enforces tests + review (+40–60 points); (b) generator capability — no measurable difference between Claude-implement and DeepSeek-implement when verification is frontier; (c) generator diversity — no effect at one shot.
  • Economics: junior/senior delivers frontier quality at −24%, bounded by the verification bill (99.6% of spend). Cheap attempts cost ~$0.015; the repair loop turns them from discarded to productive.
  • Verifier calibration is a measured cost center: the same task (token_bucket) drew a blocking HIGH from one frontier reviewer draw and a calibrated CLEAN from another; cheap reviewers add hallucination, drift, and protocol failure on top. Phase 1's refute-majority panels + numeric confidence exist to fix exactly this.

Threats to validity

  • n=5 per strategy — directional only; the 60%/60% tie and per-task flips are within reviewer-draw variance.
  • Toy tasks — honest pipeline exercise, not large-codebase navigation.
  • Substrate changed between experiments 3 and 4 (host subprocess → micro-VM guest agent): DeepSeek 1/5 → 0/5 carries an agent-implementation confound.
  • Experiment 4 costs are provider-billed totals (guest VMs don't self-report tokens yet); per-stage VM attribution reads $0 until the guest-image fix.
  • Single verifier voice per role — verdicts inherit one reviewer's temperament.
  • Claude on subscription vs OSS on metered APIs — list-price accounting for both.

What's next, by expected information per dollar

  • Repair loop (Phase 3): junior/senior + failing-gate evidence → ≤3 cheap retries before frontier escalation. The forensics above show its targets precisely: md_toc's "no code" (retry with that feedback costs $0.002) and csv_report's null-handling defect (the reviewer's refutation is a ready-made fix instruction). (~$1–2.)
  • Phase 1 verifier hardening: refute-majority panels, numeric confidence, known-bad probes, verdict-protocol enforcement for cheap reviewers.
  • Repetitions (n→15–25) on the two leading strategies.
  • Mid-tier verification to attack the 99.6% verification bill.
