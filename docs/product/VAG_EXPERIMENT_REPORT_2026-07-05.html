Open-source vs frontier models through one governed pipeline

46 governed runs, three experiments, one sample project. Every run passed through the identical fail-closed pipeline — design, independent tests, implementation, adversarial review, security review, consistency check, full-suite regression, mutation probe — with every model call metered. This is the detailed record and analysis.

The single causal finding: holding the cheap generator constant and changing only who verifies moves the pass rate from 0–20% to 60%. Verification quality — not generation quality, not model diversity — is the binding constraint. That is the VAG tenet ("the harness is the amplifier") measured on real runs. And across all 46 runs: zero false passes — nothing substandard ever shipped.

Method

Sample project. All runs target the paramg/boss-sandbox repo with a fixed suite of five deterministic, stdlib-only Python tasks — a URL slugifier, a token-bucket rate limiter, a CSV sales aggregator, a Markdown TOC generator, and an interval-merge library — each with explicit acceptance criteria and python3 -m unittest discover as the authoritative test command. Small enough to run cheaply, real enough to have edge cases (unicode, boundary values, tie-breaking, fenced-code parsing, off-by-one).

The governance pipeline (identical for every strategy). Risk tier 2–3, strict profile: standards → spec → plan → plan review (design), then a QA role authors tests before implementation exists, a separate implementer must make them pass without touching them, BOSS re-runs the tests itself, a fresh-context adversarial reviewer tries to refute the change, a security reviewer hunts exploitables, a consistency check compares code/tests/spec, the full suite re-runs, and a mutation probe plants a one-line bug expecting the tests to catch it. The gate is a fail-closed AND over all of it; PRs were suppressed (eval mode) so no repo spam.

What "model strategy" means. Per-step engine/model routing lets each pipeline role run on a different model. "Frontier" = Claude via the CLI engine (subscription). "Cheap/OSS" = open-weight models over OpenAI-compatible APIs (OpenRouter, with direct Groq/DeepSeek lanes available). The junior/senior config assigns implementation to the cheap model and keeps spec/tests/review panel on frontier.

Measurement. Every model call is recorded to a per-call telemetry table (tokens, cost, latency, retries, stage, engine, model). Costs sum from that single source; where the guest VM doesn't yet self-report usage (experiment 3), the provider's own billing delta is used instead. $ / verified outcome = total inference spend of a strategy ÷ gate-passing runs.

Substrates. Experiments 1–2 executed working stages as host subprocesses; experiment 3 ran after the hybrid refactor, with every code-executing stage in its own Firecracker micro-VM (~80 VM boots, 19/20 runs mechanically clean).

Analysis. The junior/senior config matched frontier-solo's pass rate exactly — and notably passed token_bucket, the task frontier-solo failed (different security-review draw; at n=5 treat as variance, not superiority). The saving is 24% rather than 75% because the stage the junior took over is nearly free — 99.6% of the spend is frontier design + verification. That redirects the optimization: further savings come from cheapening verification safely (mid-tier panel roles, calibration) and from making cheap attempts count (repair loops) — not from a cheaper implementer. All-DeepSeek's 20% at $0.07/outcome also seeded the ensemble hypothesis that experiment 3 then killed: its one pass suggested different models might pass different tasks. Clean negative result ($2.47 to learn it): union pass rate 0/5. The models don't fail differently enough — their failure profiles overlap on the same gates (refuted reviews, weak tests, regressions). One-shot model diversity is not a quality lever.

The confound that became the finding. In these configs the cheap model was also the reviewer — and that's visible in the data (Qwen's own security reviewer refused all five of its runs; GLM's reviewer refuted four). Compare across experiments with the generator held constant: DeepSeek-generated code judged by DeepSeek passes 0–20%; DeepSeek-generated code judged by Claude passes 60%. The verifier, not the generator, moves the outcome. Cheap verifiers are both noisier and stricter in the wrong places — so "cheap everything" fails twice: worse code and worse judgment of it.

Substrate note. This batch also stress-tested the hybrid pipeline: every write-tests / implement / regression / mutation stage ran in its own Firecracker VM (~80 boots), with tests-first commits on work branches and read-only host review. 19/20 runs were mechanically clean (one Kimi run errored mid-stage). DeepSeek scored 1/5 on the host substrate but 0/5 in VMs — the guest's simpler agent loop (JSON whole-file writes, 4 repair rounds, no editing tools) plausibly costs some capability vs the host CLI agent; worth one controlled comparison later.

Cross-cutting analysis

1 · The amplifier is trustworthy — and that's the load-bearing result

46 governed runs, 24 fail-closed refusals, zero false passes. The spec calls false confidence the one failure mode that would sink the strategy; at current sample size the gate has none. Everything else — cost, routing, ensembles — is negotiable so long as this holds. (Formal false-pass instrumentation — the known-bad probe suite — ships with Phase 1; the current claim is "nothing substandard shipped," verified by inspection of every refusal.)

2 · Where quality actually comes from

Ranked by measured effect: (a) who writes and enforces the tests/review (frontier verify: +40–60 points of pass rate), (b) generator capability (Claude implement vs DeepSeek implement: no measurable difference when verification is frontier — 60% either way), (c) generator diversity (no effect at one shot). The harness doesn't just catch bad output; frontier-authored tests appear to steer the cheap implementer onto a track it can actually follow.

3 · Economics

Cheap tokens are 20–75× cheaper, but a verified outcome is the unit that matters: junior/senior delivers frontier quality at −24% today, bounded by the verification bill (99.6% of spend). The modeled next steps: a cheap repair loop (feed the failing gates back, retry ≤N times at ~$0.01–0.03/attempt) attacks the 40% of tasks currently refused; mid-tier panel roles attack the verification bill itself. Both are spec Phase 3/1 respectively, and both now have baselines to beat.

4 · Verifier calibration is a real cost center

The security reviewer produced one true HIGH catch (an implementer added an unrequested HTTP server with a blocking-read DoS — caught, refused), one plausible false-fail (toy rate limiter), and on cheap models it becomes indiscriminate (Qwen: 5/5 refusals). Phase 1's confidence score + refute-majority panels turn these single-voice verdicts into calibrated signals.

Threats to validity — read before quoting the numbers

  • n=5 per strategy. Everything here is directional. The junior/senior vs frontier-solo tie (both 3/5, different tasks) is comfortably within noise; repetitions are cheap and queued.
  • Toy tasks. Stdlib-Python katas exercise the pipeline honestly but not large-codebase navigation, where cheap models typically degrade faster.
  • Substrate changed between experiments 2 and 3 (host subprocess → micro-VM guest agent), so cross-experiment model comparisons carry an implementation confound (DeepSeek 1/5 → 0/5).
  • Ensemble costs are provider-billed totals (guest VMs don't self-report token usage yet); per-stage attribution for VM stages reads $0 until the guest-image fix lands.
  • Single verifier voice per role. Gate verdicts inherit one reviewer's temperament per run; panel-of-N calibration (Phase 1) will tighten variance.
  • Claude runs on a subscription (CLI self-reported cost), OSS models on metered APIs — the $/outcome comparison uses list-price accounting for both, but the marginal-cost structure differs in production.

What's next, in order of expected information per dollar

  • Repair loop (spec Phase 3): junior/senior + failing-gate feedback → cheap retries (≤3) before frontier escalation. Attacks the 2/5 refused tasks at ~$0.05 marginal. The single most valuable unanswered question. (~$1–2 of the $7.42 remaining credit.)
  • Phase 1 verifier hardening: numeric confidence score, refute-majority panels, known-bad probe suite (false-pass instrumentation), security-reviewer calibration.
  • Repetitions (n→15–25) on the two leading strategies to tighten the 60%/60% tie and the −24% estimate.
  • Mid-tier verification: route consistency/security panel roles to mid-price models while keeping the adversarial reviewer frontier — attacks the 99.6% verification bill.
