# Architecture approval and model spending

Place a completed PRD panel and its PRD approval before **Architecture approval**. BOSS rereads the current workflow's adopted panel or successful panel output, the panel's project and task, and the exact PRD publication decision. An unrelated decision, another project's approval, a changed PRD or an `approved` string in a step output does not release architecture work. Older records without a verifiable typed PRD approval need a fresh panel/approval.

Each document version makes a pinned model request through the existing budget governor and model gateway. Its reservation, worker job lease, model lease and unique receipt commit before submission. The receipt stores the returned document text and usage: retrying that same version reuses the stored reply instead of paying again. A requested revision has its own receipt. The recorded workflow principal and selected architect remain attached to the job and receipt.

A spent budget or unavailable source stops the request before submission. Cancelling before submission releases the known unused reservation. If the provider outcome is unknown, paid usage cannot be priced, or authority expires after submission, BOSS retains the financial hold and opens a reconciliation decision. A received reply is kept on that receipt for inspection; it is not certified as an approved document. Inspect the receipt and resolve its liability before retrying. A quoted admission amount is not a hard limit on the provider's bill.

Architecture suppresses Smart router failover to another provider on the same receipt. Its native OpenAI/Azure request also disables SDK retries and output resampling within this one request. These checks do not certify a CLI vendor's internal billing or retry behavior. Job/model leases heartbeat during the call; expired workflow authority still refuses the document. Local scripted-provider tests qualify the BOSS boundary, while a supported installation's actual provider behavior remains a separate qualification.

After drafting, the document waits for a person. The architect, another agent and an automatic policy cannot approve it. A person can approve, reject, or request changes with a note. A revision remains bound to the original approved PRD and the current architecture review decision. Changing that PRD requires a fresh architecture review.
