# Review the first work agreement

The RC9 source adds a review sheet to the **Command Center → Review build** entry. This guide describes that source change; the published RC8 install and the setup screenshots predate it. A displayed agreement is a preview, not proof that a provider ran or that a useful result was delivered.

Write one bounded brief, then choose **Review build**. BOSS reads the current project's selected workflow and shows:

- Your complete brief, the resolved workflow and version, its starting step, paths, planned records and approval stops.
- The current repository target and base branch, where the project has an unambiguous target. The base commit remains unknown until it is read; later build admission resolves the actual task target.
- Recorded specification, acceptance checks, provider/account and financial fields. At this first planning door, an approved specification, checks, routed account, task estimate, reservation and new authorized limit do not exist yet. The sheet says so.
- Prior completed-run cost history, when available, as **API-equivalent value**. Subscription usage can be part of that value. Historical usage is not a task quote, cash charge, reservation or spending cap.

Read the actual paths and stops. The chosen workflow can differ from a standard template. A later specification or account choice remains subject to the existing identity, consent, policy and budget checks.

Choose **Cancel** to return to your retained draft. **Review again** fetches a fresh preview after an error or expiry. Neither creates a workflow run. Choose **Confirm and start workflow** only when the displayed brief and workflow are the work you intend to start. After a successful start, the console takes you to that run.

If a start response is lost, BOSS keeps the original intent and holds fresh starts in this entry. **Check start result** reads this project’s recent runs and opens only a recorded run matching that exact intent and project. No match means the outcome remains unknown; it does not prove nothing started. Closing the sheet does not clear this hold.

The preview expires after ten minutes. Starting rechecks its server binding against the current principal, project, supplied input, workflow version, referenced custom-step definitions and current repository suggestion. An edited brief, changed routing snapshot or expired preview requires another review. The binding grants no permission or financial authority; revoked access and missing consent still refuse.

If start returns a readiness checklist, review each missing prerequisite. Choosing an offered readiness exception opens a fresh agreement including those chosen keys; confirmation remains a separate action. It does not remove later execution gates.

The console stores only the opaque intent key in this tab’s session storage, scoped to the authenticated organization, project and viewer. It stores no brief, agreement token or credentials for this hold. Reloading the same tab retains it when identity and session storage are available. A closed tab, unavailable identity, blocked storage, or a run outside the recent list can prevent automatic reconciliation; inspect Workflows and reconcile the original outcome before a fresh attempt. This is not a provider cancellation or proof of zero spend.

## API boundary

The browser sends the private brief in the body of `POST /api/builds/preview`; the web server calls authenticated `POST /v1/delivery-workflows/agreement`. The API deterministically reads the canonical records. It performs no model call, provider action, budget reservation or workflow write, and stores no idempotency replay row for this read.

The response includes typed fields for the displayed agreement, a `content_hash`, an opaque `binding_token` and `expires_at_unix`. Keep the returned input and binding together. The first-build proxy requires both binding fields; the existing governed start API validates supplied bindings before any start effect. The token is issued by the server and must not be generated by a client. A repeated confirmation of the same binding is one start intent; a fresh preview receives a distinct intent.
