# Hearing an agent's voice

An agent's **Test** replies to a short probe using its composed role and persona. **Draft it** suggests a line of copy. Neither action saves a persona. Test delivers the completed reply in small SSE chunks and may then ask a second model call to judge the reply.

These are real model actions. BOSS admits each reply or judgement through a budget reservation, a canonical job with a TTL and heartbeat, a pinned model-capacity lease and an invocation receipt before contacting the adapter. A request receipt groups those invocation receipts. It records their observed cash total without creating a second cost charge. Included subscription or local capacity records zero cash and retains the existing equivalent-value accounting.

When an API caller supplies an `Idempotency-Key`, the key names one exact authenticated request: method, route, query and body, including the project and any unsaved persona. Use the original key for retries of that request. BOSS checks current project access before returning a recorded response. Reusing the key for changed input is refused. A separate intentional test uses a new key. Calls without a key remain separate requests and receive the normal SSE events.

The corrected guarantee applies to newly admitted voice intents. An ambiguous test or draft from an earlier version still needs review of its existing receipts before retrying; upgrading cannot reconstruct its discarded HTTP intent.

An initial SSE comment opens the admitted stream; it does not claim that model work started. The first HTTP headers do not finish a test. A simultaneous repeat receives `409` while the original intent is pending. BOSS yields the original stream live and records at most 1 MiB of response bytes for replay. A completely generated and recorded stream can be returned again without another model call. Completion requires the actual producer to finish its terminal event and receipt bookkeeping; an outer HTTP iterator finishing normally is insufficient. If the server observes an interrupted producer, exceeds that recording limit or fails before completion, the HTTP outcome remains unknown; a repeat is held rather than submitted again. A client closing its connection does not prove the server stopped: if the original stream is completely generated and recorded anyway, BOSS replays that record. Neither result proves that the caller received the original response. Generic ten-minute claim takeover and twenty-four-hour cleanup do not clear a committed voice intent, including its completed replay record.

A provider exception does not prove that the provider rejected a request. An uncertain call keeps its invocation receipt unresolved and retains outstanding positive financial liability. Test error/result events expose `receipt_id`, per-call `receipt_ids` and `spend_status`; `needs_reconciliation` can accompany a locally scored reply when the judgement call is uncertain. The result is not evidence that every call settled. Keyed Draft it may return `502` for an unknown first outcome and `409` when that same original intent is retried.

Read the request and invocation receipts, budget holds, job history and reconciliation decision before retrying work with an unknown provider outcome. This source change does not supply a new operator reconciliation action or recover a partial SSE response after a process restart. Committed HTTP intents remain fenced. This slice does not add a transition that releases an unresolved HTTP claim, and age never removes it. A browser that discards its original key cannot use this API guarantee to identify its previous request.

Source qualification uses disposable Postgres and an inert adapter, including actual loopback HTTP streams. It is not live provider, installed-host, or customer-usefulness qualification.
